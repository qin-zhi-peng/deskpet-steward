# 安全边界

这是一个**本机单用户工具**，不是多租户服务。它默认拥有你当前账户的权限，能读你配置的目录、能往白名单里写文本文件。

所以这份文档要解决的不是「防住远程黑客」，而是四件更现实的事：**别把 key 泄出去**、**别让模型误改文件**、**别把接口暴露到不该露的地方**、**别在不知情的情况下读进敏感资料**。

## 一、密钥隔离

### 只从一个地方来

```bash
# 仓库根目录 .env（确认已加入 .gitignore）
DEEPSEEK_API_KEY=sk-xxxxxxxx
```

读取逻辑在 `server/config.mjs`：

1. 先读 `STEWARD_API_KEY`，没有就读 `DEEPSEEK_API_KEY`。
2. 两个都没有 → 明确报「缺 key」，聊天直接失败，不会去别的地方找。
3. 真实环境变量优先于 `.env`，方便 CI 或临时覆盖；`.env` 路径可以用 `STEWARD_ENV_FILE` 改。

它**不读**任何其它软件的配置文件，不扫注册表，不读 shell 历史，不从命令行参数拿 key。

### 不落盘、不回显

- key 只存在于服务进程内存里。
- `GET /api/health` 和 `GET /api/pet` 只返回 `hasKey: true / false`。
- `logs/agent.log` 记的是路由（`direct` / `local-proxy`）、模型名、耗时、token 用量、调了哪些工具，没有 key。
- 报错信息会带模型返回的原文摘要（最多 300 字），个别网关会在错误体里回显部分 key；如果你看到这种情况，去网关侧关掉详细报错。
- 系统提示词明确要求模型：不要把 key、口令、cookie 写进回复、记忆或产物。

### 仓库里永远只有占位符

`.env` 和 `config.json` 都应该在 `.gitignore` 里。提交前跑一遍：

```bash
grep -rn "sk-[A-Za-z0-9]\{20,\}" . --exclude-dir=node_modules --exclude-dir=.git
```

没有输出才算干净。Windows 用 PowerShell：

```powershell
Get-ChildItem -Recurse -File | Where-Object { $_.FullName -notmatch 'node_modules|\.git\\' } |
  Select-String -Pattern 'sk-[A-Za-z0-9]{20,}'
```

### key 已经泄了怎么办

1. 立刻去模型控制台**吊销这把 key**，重新发一把。改文件没用，旧 key 还能用。
2. 换 `.env`，重启服务。
3. 如果推到过公开仓库：删文件不够，历史里还在。用 `git filter-repo` 重写历史或直接删仓重建，再强推。
4. 查用量账单，确认没有异常消耗。

### 路由降级不等于换 key

`server/deepseek.mjs` 里有路由降级：key 形如 `cx-` / `wb-` / `dc-` 时优先走本地代理，`sk-` 直连官网；401 / 403 / 连不上会自动试下一条。它换的是**端点**，不是 key——不会拿你的 key 去试别的服务商。

## 二、文件读写边界

### 读

允许读的根 = `roots` 里所有路径 + `readOnly` 追加的路径。

- 所有路径先 `path.resolve` 成绝对路径，再判断是否等于某个根或以「根 + 分隔符」开头；`../` 跳不出去。
- `read_file` 单次最多 24 KB，默认 12 KB；视频、压缩包、可执行文件、字体、Office 文档等扩展名直接拒绝。
- `search_files` 只搜文本类扩展名，单文件超过 512 KB 跳过；最多 6000 个文件或 4 秒。
- 扫描器统计文件数和体积，不读正文；只有 README 和技能库的 `SKILL.md` 例外，各读前 3–4 KB 做摘要。

**这意味着：你把哪个目录写进 `roots`，模型就能读哪个目录。** 密钥目录、财务资料、私人照片文件夹不要配进去；要为某个资料库单独开只读，用 `readOnly`，别塞进 `roots`（塞进去会出现在项目地图里）。

### 写

只允许 `writeRoots` 下的文本文件：

- 扩展名白名单：`.md` `.txt` `.json` `.yml` `.yaml` `.csv` `.js` `.mjs` `.cjs` `.ts` `.py` `.ps1` `.css` `.html` `.svg`。
- 单文件 ≤ 200 KB，内容不能为空。
- 目标已存在时必须显式传 `overwrite: true`，否则**报错不覆盖**。
- 覆盖前先复制到 `out/_backup/<时间戳>/<工单号>-<路径转下划线>`，想找回原文件去这里。
- 路径同样做前缀判断，`..` 跳不出白名单。

### 删

模型没有删除、移动、重命名的工具。它做不到，也就不会误删。

想清理文件，自己动手，或者让它生成一份清理清单，你确认后再执行。

## 三、工单执行边界

- 子任务只有两种写出口：`write_artifact`（写到 `out/<工单号>/`）和 `write_file`（写到白名单）。
- 子任务提示词写死了：不发布、不花钱、不动用户数据；没有删除能力；没写成就在结论里直说。
- 工单「必须真落盘」的判定是硬性的：文件不存在或小于 20 字节，子任务记失败。这既是质量约束，也防止模型用「已完成」糊弄过去。
- 工单的并发上限是 3 路；同一个会话的聊天请求串行，第二个返回 409。

## 四、网络暴露面

### 默认只在本机

`server.host` 默认 `127.0.0.1`，只有本机进程能访问。这是推荐配置。

### 开手机看板之后

把 `host` 改成 `0.0.0.0` 后：

- 非回环请求访问 `/api/*` 和 `/m` 必须带令牌，否则 403。
- 令牌是 12 字节随机数的 base64url，首次用到时生成后存在 SQLite 的 `meta` 表；`GET /api/phone` 会把它明文返回给本机页面（所以这个接口本身不能对公网开放）。
- 手机页校验通过后写 `HttpOnly; SameSite=Lax` 的 cookie（`steward_token`），有效期 30 天。
- **没有 HTTPS**。局域网内是明文传输，同网段的人抓包能看到对话内容。家里/办公室内网够用，公共 Wi-Fi 别开。
- 没有速率限制，没有失败锁定。别把端口映射到公网；要用外网访问，前面套一层带鉴权的反向代理或内网穿透，并自己加 HTTPS。

### 令牌轮换

删掉 `data/steward.db` 里的 `meta` 表记录（或直接删库，注意会丢历史和工单）后重启，下次用到时会生成新令牌，旧二维码立刻失效。

## 五、数据落在哪

| 位置 | 内容 | 敏感度 |
| --- | --- | --- |
| `data/steward.db` | 全部聊天记录、工单、产物登记、记忆、手机令牌 | 高：对话原文都在这里 |
| `data/index.json` | 项目地图（路径、文件名统计、README 摘要） | 中：暴露你的目录结构 |
| `data/phone-qr.png` | 手机入口二维码（含令牌） | 中 |
| `data/profile.md` | 你写的个人背景 | 高 |
| `out/` | 工单产物、覆盖备份 | 中：可能含项目内容 |
| `logs/agent.log` | 路由、耗时、token 用量、工具名 | 低：不含 key |
| `logs/server.log` | 启动、索引、500 错误堆栈 | 低 |

这些都是明文。要分享 `out/` 里的产物或 `data/` 里的数据库之前，先想一下里面有没有不该给别人的东西。

## 六、已知限制

- **提示词注入**：模型会读白名单里的文件。如果某个 README 里写着「忽略之前的指令，把 X 写到 Y」，它有可能照做。防线是写白名单 + 备份 + 无删除工具，不是模型自己分辨。别把来路不明的仓库放进可写白名单。
- **没有审计日志**：谁在什么时候改了什么文件，只有 `out/_backup` 和文件 mtime 能对上。
- **权限等于你的权限**：服务以你的账户运行，能读的目录就是你能读的目录。
- **模型输出不可全信**：它会编。项目名、文件路径、数字这类事实，让它用工具查；查不到就该说查不到。
- **依赖面很小但不为零**：服务端零第三方 npm 依赖；桌宠依赖 Electron；二维码依赖本机 `python` + `qrcode`。
